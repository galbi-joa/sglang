# 工作日志 (2026-06-08) — prefill claim 确认 + 文档整理

## 今日结论（claim 确认）

- 确认了 claim：在 prefill 阶段，trtllm-gen 确实比 FlashMLA 快。
- FlashMLA 的专用 prefill kernel（`flash_mla_sparse_fwd`）只支持 bf16。
- trtllm 原生支持 fp8，是 FlashMLA 在 prefill 阶段性能不佳的根本原因。
- FlashMLA 想用 fp8，只能借它的 fp8 decode kernel（`flashmla_kv`）来做 prefill。
- 但用 `flashmla_kv` 做 prefill 仍然比 trtllm 慢。

## 沿用前几日的结论（供参考）

- fp8 sparse_decode 的 `Missing TRTLLM-GEN kernel` 是 dispatch 失败：flashinfer 强制
  `q dtype == KV dtype`，把 trtllm query 也转 fp8 即解决（2026-06-05）。
- `flash_mla_sparse_fwd` 是实在的专用 sparse prefill kernel，并非 decode kernel 复用
  （cmake/op 追踪确认，2026-06-05）。
- `flashmla_kv`（decode kernel 当 prefill）在 B≥16 会撞 shared memory 上限（280KB > 232KB），
  退到低共享内存 fallback（2026-06-05）。
